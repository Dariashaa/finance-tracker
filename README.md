# Личный финучёт

Веб-приложение для учёта личных доходов и расходов: операции, категории, бюджеты, отчёты и экспорт данных.

> Статус: лабораторная работа №1. Реализован frontend на демонстрационных данных. Backend (FastAPI + PostgreSQL) будет добавлен в следующих работах.

## Назначение

Приложение помогает видеть, сколько человек зарабатывает и тратит, на что уходят деньги и укладывается ли он в запланированные лимиты по категориям.

## Основные пользовательские сценарии

1. **Добавить операцию**: указать сумму, дату, категорию и комментарий (расход или доход).
2. **Просмотреть операции за период**: выбрать месяц, увидеть итоги (доходы, расходы, баланс).
3. **Отредактировать или удалить операцию**, если допущена ошибка.
4. **Управлять категориями**: создать, изменить название и цвет, удалить.
5. **Задать бюджет**: установить месячный лимит расходов по категории и видеть, сколько уже потрачено.
6. **Посмотреть отчёты**: расходы по категориям, динамика доходов и расходов по месяцам.
7. **Экспортировать данные** за выбранный период в CSV.

## Экраны

### 1. Главная (операции) — `/`

- Сверху: выбор месяца и три карточки итогов (доходы, расходы, баланс).
- Две колонки: **слева расходы, справа доходы**. В каждой: заголовок с суммой за месяц, кнопка «+ Добавить» и список операций.
- Операция отображается компактной строкой: дата, описание (комментарий или название категории), цветной бейдж категории, сумма со знаком и цветом.
- Клик по строке открывает окно редактирования.
- На узких экранах колонки располагаются друг под другом.

### 2. Категории и бюджеты — `/categories`

- Категории в двух группах: расходы и доходы.
- Строка категории: цветная точка, название, «потрачено / лимит», полоска прогресса, кнопки «изменить» и «удалить».
- Цвет полоски: зелёная до 70%, жёлтая 70-100%, красная при превышении (с подписью, на сколько превышен лимит).
- Лимит необязателен: без лимита полоска не показывается. У категорий доходов бюджета нет.
- Выбор месяца: «потрачено» считается по операциям выбранного месяца.

### 3. Отчёты — `/reports`

- Выбор периода: весь период или конкретный месяц.
- Круговая диаграмма расходов по категориям (цвета совпадают с цветами категорий).
- Столбчатая диаграмма доходов и расходов по месяцам.
- Кнопка **«Экспорт CSV»** выгружает операции выбранного периода (разделитель `;`, кодировка UTF-8 с BOM, открывается в Excel).

### 4. Модальные окна

- **Операция** (добавление и редактирование): сумма, дата, категория (только нужного типа), комментарий. При редактировании доступна кнопка «Удалить».
- **Категория** (создание и редактирование): название, тип, цвет, лимит (только для расходов).

## Технологии

- **React 19 + TypeScript**, сборка через **Vite**
- **MUI (Material UI)**: библиотека UI-компонентов, единая тема оформления в `main.tsx`
- **React Router**: клиентская маршрутизация
- **Recharts**: графики на странице отчётов
- **Git**: контроль версий

В планах на следующие работы: backend на Python + FastAPI, база данных PostgreSQL + SQLAlchemy.

## Запуск frontend

Требуется Node.js (актуальная LTS-версия, 20.19+ или 22.12+) и npm.

```bash
git clone <адрес репозитория>
cd finance-tracker
npm install
npm run dev
```

После запуска приложение доступно по адресу, который покажет Vite (обычно http://localhost:5173/).

Другие команды:

```bash
npm run build     # сборка для production с проверкой типов
npm run preview   # просмотр собранной версии
npm run lint      # проверка кода линтером
```

Секретов и переменных окружения на этом этапе нет: приложение работает на демонстрационных данных.

## Принятые решения

- Лимит категории один и действует на каждый месяц; «потрачено» считается по операциям выбранного месяца.
- Категорию, в которой есть операции, удалить нельзя: приложение показывает предупреждение. Тип существующей категории менять нельзя.
- Цвет категории задаётся один раз и используется в списках, бейджах и графиках.
- Суммы хранятся положительными числами, знак «+» или «−» определяется типом операции при отображении.
- Данные на этом этапе хранятся в состоянии приложения (React Context), начальные значения берутся из демо-данных. После перезагрузки страницы изменения сбрасываются; постоянное хранение появится вместе с backend.

## Изменения относительно первоначального замысла

- **Экспорт** вынесен не на отдельную страницу, а в кнопку на странице отчётов: период уже выбран там, а отдельный экран ради одной кнопки избыточен.
- **Категории и бюджеты** объединены в один экран: бюджет является лимитом категории расходов.
- Добавление и редактирование сделаны модальными окнами, чтобы пользователь не уходил со страницы.
- Для адаптивности вместо `Grid` используется `Stack` с разным направлением на разных размерах экрана: так проще и одинаково работает в разных версиях MUI.
